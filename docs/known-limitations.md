# 已知限制与取舍

这套系统以「不替你学习」为第一优先级，因此牺牲了一些便利。以下是实测或明确的设计边界。

## 1. 同步对话：不能异步预生成反馈

- **现象**：主动回忆必须先提问并结束回复，等你作答后才能反馈。
- **原因**：预生成答案会泄露结论，也会让 AI 代替你思考。
- **代价**：无法并行，长会话轮次多。
- **缓解**：一次只问一道核心问题；把项目进展、资料、问题背景一次性给足；不重复读取同一来源；长会话及时收尾。

## 2. 单轮约 2 分钟

- **实测环境**：opencode-go 订阅 + `glm-5.3-flash`，单次交互约 2 分钟。
- **影响**：多轮回忆、复盘的时间成本高。
- **缓解**：减少轮次；批量输入；把「查资料」和「回忆」拆成两次会话；复盘前先自己整理草稿。

## 3. DeepSeek v4.1 不兼容

- **现象**：其输出格式偏好与本工作流冲突（思源 Markdown / 结构化回合）。
- **处理**：当前不使用 `deepseek-v4.1`；推荐 `glm-5.3-flash` 或输出格式稳定的模型。
- **说明**：换模型前先用一个小流程（整理一个资料页或做一次回忆）验证格式，再投入长会话。

## 4. 无后台能力

- 不监控社区更新，不自动拉取新版本，不打卡，不自动评分。
- 不记录未发生的学习，不推断未展示的能力。
- 需要更新时显式发起。

## 5. 依赖思源与 Agent 能力

- 工作区约定依赖思源 3.8.8+ 的 AI 指令 / 技能机制，不同版本路径可能不同。
- 文档按标题定位，首次使用需要「校准」；标题被大幅改名后需重新校准。
- 检索能力以实际测试为准：「已收藏」「可搜索」「语义召回可用」是三件事。

## 6. 模板是骨架，不是评分表

- 零必填；缺项保留未知，不用占位符假装完成。
- 不设「填完才能开始」的流程。
