# 设计原则

四条原则是这套系统的约束，不是口号。任何流程、模板、Agent 指令都应能回溯到其中一条。

## 1. 项目优先

**先推进真实项目，资料与学习服务于项目，用产出推进学习。**

- 没有真实项目时，不为了维护系统而制造任务。
- 资料、学习笔记、能力评估都回答同一个问题：它是否服务于当前项目或下一步？
- 产出优先于「学完」：能运行、能解释、能比较，才算推进。
- 纯学习与兴趣探索可以独立存在，但不替代项目主线。

## 2. 筛选输入

**只选择高质量内容作为参考，不导入任何未经精校的 AI 内容。**

- 进入参考资料的是原始论文、官方文档、课程、可追溯的技术报告。
- AI 生成的摘要、解读、综述默认不进入资料库；确需保留时标明为草稿，并与原文分开。
- 收藏不等于学习，也不自动变成任务。资料页只记录出处、版本、覆盖范围与标签。
- 质量判断需要具体理由：来源、证据、适用条件、时效。社区热度不算证据。

## 3. 原文即数据

**原文就是最好的数据，除论文时间、发表单位等客观内容外，不对高质量内容进行任何二次加工。**

- 资料页优先保留原文结构，不做概述性导读，不替原文补写条件。
- 需要摘录时保留上下文与版本；自己的理解写进「我的笔记」，不混入资料页。
- 冲突时回到原文核对，不用二手转述拼接结论。
- 客观元数据（作者、年份、发表单位、会议、链接、版本）可以整理，内容本身不改写。

## 4. 反馈学习

**讲就是学，做就是学，阅读资料后通过自我讲解重新建立神经突触。**

- 关键学习单元结束后，必须先由本人用自己的话复述或推导。
- Agent 先提问，然后停下来等待；不提前给答案、答案摘要或泄露结论的提示。
- 「想不起来」也算一次尝试，但不算独立掌握；一次答对也不等于长期掌握。
- 反馈要指出成立之处、遗漏与误解，并保留本人原话作为证据。
- 输出形式不限：几句话、图示、推导、口述记录都可以。

## 原则之间的关系

- 项目决定学什么（1），输入决定拿什么学（2），原文保证学的是真东西（3），复述保证真的学会（4）。
- 四条同时生效；冲突时优先保证项目推进与真实证据，不为系统完整性制造额外劳动。
