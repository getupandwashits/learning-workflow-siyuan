# 复盘与成长评估

## 位置

- 默认笔记本：学习与成长；项目：项目；个人笔记：我的笔记；阶段复盘：随手记录与阶段复盘。
- 方向：成长档案 / 方向与约束；能力与证据：成长档案 / 能力与证据；首页：首页。
- 首次使用时按标题定位；可把实际 ID 记录到 `AGENTS.md` 的「位置」一节。
- 先读取相关原记录，再用思源工具局部更新或建立引用；不直接编辑 `.sy`。
- 按实际需要读取「模板入口」下的对应模板，不要求用户先填满模板。

## 汇总真实记录

1. 确认本次涉及的项目或时间范围，读取项目起点、近期进度、个人心得、回忆与旧复盘；按需沿引用补上下文，不仅凭一次语义召回结论。
2. 先整理已有记录，再追问真正影响判断的缺失信息。用户可以自然叙述，不要求重新填一张完整表。
3. 区分用户报告、可核实结果、外部来源与 AI 假设。整理到「推进到哪里／变化与障碍／理解与能力／调整与下一步」。不能从没有记录推断用户没做或不会。
4. 项目层面的事实写回原项目；跨项目阶段总结保存在复盘入口，并引用原记录，避免复制全部经过。

## 比较能力

选择与本阶段有关的少量可观察能力，按理解、实现、诊断判断或迁移等实际维度描述，不要求所有项目覆盖所有维度。

比较起点和当前表现时，明确任务难度、熟悉程度、能否查材料、提示、AI／他人贡献和结果核实程度。条件不同的表现不直接相减。

每项重要判断保留：能力动作、起点、当前表现、具体证据引用、仍不确定的部分和建议的下一步。只有当前证据时只描述当前能力；只有自述时注明自述；没有可比基线时不编造成长幅度。

项目完成、主动回忆完成和个人掌握分别判断。AI 或团队完成的工作可以推进项目，但不直接归为用户掌握。一次独立答对只能支持相应范围的表现。

保留带日期的起点和判断演变。将有证据的变化建议写入能力档案，并标出暂定判断供用户集中修正；不改写用户原始结论。不默认总分、百分比或排名。

## 调整与输出

提出少量下一步：项目动作、补学前置、完成待回忆、选择性复习或探索。说明为什么现在做、依据是什么、服务哪个目标与能力，以及从哪里开始。建议与已选任务分开，避免自动增加待办。

普通进度记录不追加全面测试。阶段完成、重要问题解决或用户要求时进行较完整比较；期间关键学习仍须先有个人提取，再核对反馈。

相关经验可连接到原则／概念笔记；不要为每条原则编造应用案例。允许停止、搁置和改变计划，不设置精力模式、打卡或补齐全部历史欠账的要求。

## 首页同步

本次实际新增项目、学习任务、待回忆、资料质量标记或复盘时，读取首页，仅局部更新对应小节的原块引用，保留用户正文。项目任务原块在项目笔记，独立学习任务原块在学习笔记；首页只引用原块，不复制另一套复选框或状态。没有实际记录变化时不为刷新首页制造条目。

回复链接到复盘与原项目，清楚说明可信的变化、尚缺的证据和最有价值的下一步。信息不足时保留未知，不以漂亮的总结替代真实成长。

## 动态知识与成长边界

阶段复盘按需核验当前真正相关的少数仓库或资料，说明变化、影响、是否调整及依据；没有核验就不声称最新。不监控全社区，也不自动迁移版本或改写全部计划。

保留旧资料与判断的版本条件，不因接口改动将过去理解判为错误或能力退步。个人解释、方案辨析与边界分析可以形成知识成长证据；未实际实现或运行就不写成实现、调优能力。后续建议优先贴合当前阅读和项目目标，实践只按用户明确的项目需求安排。
